# Mitigating BadUSB and Keystroke Injection Attacks

## Threat Model
Keystroke injection attacks exploit an inherent architectural assumption of operating systems: any device presenting itself as a USB Human Interface Device (HID) is an authentic, human-operated keyboard.

## Key Defenses

### 1. Hardware Allow-Listing (Device Control)
Modern Endpoint Detection and Response (EDR) agents and Mobile Device Management (MDM) platforms allow administrators to block unauthorized USB classes:
- Block all new USB HID devices unless explicitly authorized by hardware serial number or device GUID.
- Restrict USB ports exclusively to recognized hub topologies.

### 2. Keystroke Anomaly Detection
Typing speeds generated by microcontroller firmware typically exceed human typing cadence (e.g. sub-50 ms inter-key delays with zero variance). Host-side software can monitor:
- Unusually uniform key-press intervals.
- Instantaneous typing bursts immediately upon device connection.

### 3. Execution Prevention
Even if keystrokes are accepted by the host OS, locking down execution rights drastically limits potential exposure:
- Enforce PowerShell ConstrainedLanguage mode or strict execution policies.
- Utilize Application Whitelisting (e.g. Windows Defender Application Control / AppLocker).
- Restrict access to `Run` dialogs (`Win + R`) and administrative command prompts for non-privileged user accounts.
